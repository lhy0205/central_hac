# MCM Nomad Passport — 개발 브리핑

> 이 문서는 기획 단계에서 나온 모든 결정사항을 개발 시작 시점에 넘기기 위한 정리본입니다.

---

## 1. 프로젝트 개요

- **해커톤**: 멋쟁이사자처럼 대학 14기 중앙 해커톤 (ANIMAL LEAGUE)
- **트랙**: SJF (성주재단·MCM), Challenge 03 — 360° 고객경험
- **한 줄 정의**: 제품의 생애주기를 기록하고, AI가 관리와 재구매의 최적 시점을 제안해 구매 이후에도 브랜드와 고객의 관계를 이어주는 디지털 여권
- **핵심 문제**: 구매 이후 관계 단절 — 고객의 제품 상태 데이터가 없어 적절한 케어·재구매 접점을 만들기 어렵다

## 2. 솔루션 구성요소

| 구성요소 | 역할 |
|---|---|
| **Passport** | 제품별 구매·진단·케어·사용 이력을 축적하는 데이터 그릇 |
| **Verified Patina** | 사진을 통해 마모·코팅 벗겨짐·변색·부자재 상태를 평가 |
| **Lifecycle Curator** | 제품 상태와 사용 맥락을 근거로 셀프케어·공식수선·재구매 시점을 제안 |
| **Concierge** | 여권 기록을 활용해 구매 전·중·후 경험을 연결하는 고객 인터페이스 (MVP 범위 밖, 로드맵) |

핵심 원칙: 모든 알림에는 상태 점수·변화량 같은 판단 근거를 함께 표시해 "왜 지금 이 알림을 받았는지"를 항상 알 수 있게 한다.

## 3. 기술 스택 (결정됨)

- **프론트엔드**: React — **반응형 웹**으로 진행 (네이티브 앱/PWA 아님)
- **백엔드**: Spring Boot
- **사진 촬영**: 네이티브 앱 카메라 API 아님. `<input type="file" accept="image/*" capture="environment">` 방식으로 모바일 브라우저에서 카메라 직접 호출
- 저장소(DB) 등 세부 스택은 아직 미정 — 백엔드 담당(정준영)이 Spring Boot 경험 있음

## 4. MVP 범위 — 반드시 구현할 것 (우선순위 순)

데모 목표: **"제품 등록 → 사진 진단 → 근거가 있는 타이밍 알림 → 여권 타임라인 갱신"** 한 흐름을 완성도 있게 보여주는 것. 나머지는 확장 로드맵으로 슬라이드에서만 설명.

### 4-1. 회원 및 계정 관리
- 회원가입(이메일/소셜), 로그인/로그아웃(세션 유지), 비밀번호 재설정
- 프로필 관리, MCM 기존 멤버십 계정 연동(구매이력 반영), 회원 탈퇴

### 4-2. 여권 생성 & 제품 등록 (Passport 생성)
- 시리얼 번호 스캔(카메라 OCR) 또는 수동 입력 폴백(오타 방지용 재입력 확인 포함)
- 모델 선택, 구매 정보 입력(구매일·구매처)
- 구매 영수증 첨부 → [구매 증빙 완료] 태그 부여 / 미첨부 시 "영수증 없음"으로 등록 가능
- 정품 검증: 시리얼 유효성 + 타 계정 중복 등록 여부 확인(중복이면 거부)
- 베이스라인 사진 업로드(초기 상태 기준점, 이후 진단 비교용)
- 애칭 설정, 최초 등록 완료 온보딩

### 4-3. 마모 진단 (Verified Patina)
- 촬영 가이드 UI (모서리·손잡이·바닥면·금속 부자재 등 부위별 안내)
- 사진 업로드(촬영/갤러리), 이전 사진과 비교 가능하도록 첨부
- 상태 분석: 마모·코팅 벗겨짐·변색·부자재 상태를 항목별 평가 → MVP는 규칙 기반 시뮬레이션으로 충분
- 진단 결과: 항목별 점수 + 종합 등급(양호/관리 필요/시급) + 판정 근거 문장
- 변화 추이: 이전 진단과 비교 시각화
- **자가진단 vs 매장 공식진단 구분 태깅** (매장 진단이 더 높은 신뢰도로 기록)
- 진단 이력: 시리얼 번호에 귀속되어 누적 조회
- 재진단 주기 안내/리마인드

### 4-4. 타이밍 알림 (Lifecycle Curator)
- 권장 시점 산출: 마모도·사용빈도·계절·구매일 종합
- 근거 표시: "왜 지금"을 판단 인자 분해해서 제시 (알림 카드에 항상 노출)
- 알림 유형 분기: 셀프케어 안내 / 공식 서비스(매장) 예약 연결 / 재구매 제안
- 셀프 케어 가이드(소재별·증상별), 케어 기록 저장
- 알림 이력 관리(읽음/무시 여부)

### 4-5. 여권 타임라인
- 개체별 독립 여권, 타임라인 UI(등록·진단·케어 이력이 스탬프 형태로 시간순 표시)
- 이벤트 상세보기(스탬프 클릭 시 해당 시점 기록 확인)
- 사용자 직접 이벤트 추가(사진+메모)
- 내 컬렉션: 보유 제품 목록, 상태등급·소유기간·최근진단일 요약, 정보 수정/삭제

## 5. 확장 기능 — MVP 이후 로드맵 (발표에서는 슬라이드로만 설명, 개발 우선순위 낮음)

- **인증서 발급**: 진단 횟수·케어 이력·현재 등급 확인, 진위 확인(QR), PDF 다운로드/공유
- **리세일 & 승계**: 소유권 이전, 이력 승계(이전 소유자 정보 마스킹), 새 소유자 온보딩, 이력 공유 링크, 소유 해제, 공식 리세일 채널 연결
- **발견 & 추천**: 여권 이력 기반 맞춤 추천(+근거 라벨), 스타일 추천, 헤리티지 아카이브, 위시리스트
- **매장 경험**: 매장 찾기, 매장 체크인(타임라인 자동 기록), AR 헤리티지, 구매 순간 "첫 페이지 연출"
- **리캡 & 게이미피케이션**: 연말/누적 리캡, 파티나 시그니처(패턴 시각화), 스티커/뱃지, 마일스톤 알림, 월간 관리 리포트
- **설정 & 지원**: 언어 전환, 개인정보 관리, 고객센터

## 6. 상세 기술 시나리오 (팀 브레인스토밍에서 나온 구체적 흐름 — 백엔드 설계 참고용)

### 최초 등록 (영수증 있음)
플레이트 시리얼 스캔 → 중복 등록 확인(이미 등록된 시리얼이면 거부) → 구매 영수증 첨부 → [구매 증빙 완료] 태그 부여 → 베이스라인 사진 3장 업로드 → 등록 완료

### 최초 등록 (영수증 없음, 빈티지/오래된 제품)
플레이트 시리얼 스캔 → 중복 확인 → "영수증 없음" 선택 → 태그 없이 등록 → 베이스라인 사진 업로드 → 등록 완료. 이후 매장 공식진단을 쌓아가며 신뢰도 보완

### OCR 인식 실패 (스크래치/반사)
플레이트 스캔 시 OCR 실패 → 수동 입력 화면 전환 → 번호 입력 → 오타 방지를 위해 동일 번호 재입력 요구 → 일치 시 플레이트 사진(흐릿해도 무방) 첨부 → 이후 정상 등록 흐름과 동일하게 진행

### 정기 진단
- 자가진단: 주기 알림 → 3장 촬영·업로드 → AI 등급 산출 → "자가진단" 태그
- 매장 공식진단: 매장 방문 시 직원이 진단 진행 → "매장 공식진단" 태그로 더 높은 신뢰도 기록

### 이력 공유 (마스킹 적용, 확장 기능)
소유자가 "이력 공유 링크 생성" → 고유 URL/QR 발급 → 거래 상대가 QR 스캔 → 시리얼·등록일·구매증빙 태그·자가/매장 진단 횟수와 등급(텍스트만)·리페어 이력만 노출 → 소유자 이름·계정ID·영수증 원본·진단 원본 사진은 전부 마스킹

### 소유 해제 / 인수 (확장 기능)
- 소유 해제: "내 가방" 목록에서 개체 선택 → 확인 모달 → 상태가 "해제됨"으로 전환, 활성 목록에서 제거, 진단 알림 중단. 이력은 보존
- 인수: 이력 공유 링크 접속 → 로그인 상태면 "이 가방 내 걸로 가져오기" 버튼 노출 → 클릭 시 소유자가 새 계정으로 갱신, 기존 이력 유지

### 데이터 모델 초안 (모듈별)

| 모듈 | 입력 | 처리 | 출력 | 저장 데이터 |
|---|---|---|---|---|
| 로그인/계정 | 이메일+비밀번호 또는 소셜 로그인 | 자체 계정 시스템 (MCM 앱 계정 연동 여지 있음) | 로그인 → 내 가방 목록 | 계정ID, 이메일, 등록된 개체ID 목록 |
| 시리얼 등록 | 플레이트 사진(+영수증 선택) | OCR 추출 → 실패 시 수동입력+재입력 확인 폴백 → 중복 등록 확인(거부) → 영수증 유무로 태그 결정 | 등록 완료 + 베이스라인 사진 업로드 요청 | 개체ID, 등록일, 소유자(계정ID), 구매증빙 태그 여부, 영수증 이미지(비공개), 베이스라인 이미지 |
| 정기 진단 | 사진 3장 + 이전 사진 + 진단 유형 | 이미지 비교로 등급 산출(MVP는 규칙기반 시뮬레이션), 진단 유형 태깅 | 진단 카드(등급/유형) + 매장 예약 CTA(자가진단 시) | 진단ID, 개체ID, 일시, 사진(비공개), 등급, 진단유형 |
| 인증 이력 타임라인 | 없음(조회) | 등록·진단·리페어를 시간순 정렬, 매장진단 강조 | 타임라인 UI(소유자 본인 뷰) | 이력 로그 |
| 이력 공유 링크(확장) | 공유 요청 | 이력 요약을 고유 URL 페이지로 렌더링 → 개인정보 마스킹 필터 적용 | 마스킹된 실시간 조회 URL + QR | 공유링크ID, 개체ID, 생성일 |
| 소유 해제(확장) | 해제 요청 | 개체 상태 active → released 전환 | "해제 완료" 안내 | 개체 상태, 해제일시 |
| 인수(확장) | 이력 공유 링크 + 인수자 로그인 | released 상태 확인 → 소유자를 인수자 계정으로 교체, active로 재전환 | "내 가방에 추가됨" 안내 | 소유자 갱신, 인수일시 이력 기록 |

## 9. 개발 시작 시 우선 처리할 것

1. Spring Boot 프로젝트 초기 세팅 + DB 스키마 설계 (위 6번 데이터 모델 초안 기준)
2. React 프로젝트 초기 세팅, 카메라 업로드 컴포넌트(`<input capture>`) 프로토타입
3. 4-2(제품 등록) → 4-3(마모 진단) → 4-4(타이밍 알림) → 4-5(타임라인) 순으로 화면 단위 구현
4. 마모 진단 로직은 MVP 단계에서 규칙 기반(색상 대비, 밝기 분석 등)으로 시작 — AI/데이터 담당과 협의 필요
