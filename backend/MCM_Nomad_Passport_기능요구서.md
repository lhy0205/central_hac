# MCM Nomad Passport — 기능 요구서 (Functional Requirements Document)

- **버전**: v1.1
- **작성일**: 2026-08-12 (기획서 2차개정 + 오태훈 멘토 2차 리뷰 반영본 기준)
- **참고 문서**: `MCM_Nomad_Passport_기획서_2차개정.docx`, `MCM_Nomad_Passport_구조_요약.md`, `MCM_Nomad_Passport_백엔드_신규구현사항.md`
- **범위**: 백엔드 API 기준 기능 요구사항. 프런트엔드 화면 명세는 별도 와이어프레임 참고

---

## 1. 개요

MCM Nomad Passport는 제품(가방) 단위로 디지털 여권을 발급해, 구매·진단·케어·소유권 이전 이력을 시간순으로 기록하고, 진단 결과를 근거로 관리·재구매 시점을 제안하는 서비스다. 이 문서는 백엔드가 구현해야 하는 기능을 도메인별로 정리한다.

## 2. 액터

| 액터 | 정의 |
|---|---|
| 소유자(Owner) | 제품을 등록하고 여권을 소유·관리하는 회원 |
| 매장 직원(Store Staff) | 공식 진단·케어 접수를 수행하는 역할. 별도 계정 체계 없이 소유자 계정의 진단 요청 시 `diagnosisType=STORE`로 구분(MVP 기준, 매장 직원 전용 로그인은 범위 밖) |

## 3. 기능 요구사항

각 항목은 `FR-도메인-번호` 형식으로 식별한다.

### 3.1 계정 (Account)

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-ACC-01 | 회원가입 | 이메일+비밀번호로 가입. 이메일 중복 시 409 | 필수 |
| FR-ACC-02 | 로그인 | 이메일+비밀번호 검증 후 JWT 발급 | 필수 |
| FR-ACC-03 | 내 프로필 조회/수정 | 닉네임 등 기본 정보 조회·수정 | 필수 |
| FR-ACC-04 | 비밀번호 재설정 | 토큰 발급 → 이메일 발송(또는 데모용 노출) → 토큰 확인 후 변경 | 필수 |
| FR-ACC-05 | 회원 탈퇴 | 소프트 삭제. 소유 Passport 전체 `status=DELETED`로 연쇄 처리 | 필수 |
| FR-ACC-06 | 소셜 로그인 | 카카오/구글 등 | 범위 밖(로드맵) |
| FR-ACC-07 | MCM 멤버십 연동 | 외부 시스템 연동 | 범위 밖(로드맵) |

**수용 기준**
- 탈퇴한 계정으로는 로그인 불가
- JWT 만료 시 모든 인증 필요 API가 401 반환

### 3.2 여권 생성 & 제품 등록 (Passport)

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-PSP-01 | 제품 등록 | 시리얼(수동입력) + 모델명 + 구매정보(purchaseYear는 구매일에서 자동 추출) + 영수증(선택) + 베이스라인 사진 + 사용빈도 입력받아 Passport 생성 | 필수 |
| FR-PSP-02 | 시리얼 형식 검증 | 신형 `^[A-Za-z]\d{4}$` / 빈티지 `^\d{4}$` 정규식 검증 | 필수 |
| FR-PSP-03 | 중복 등록 방지 | `(serialNumber, purchaseYear)` 조합에 대해 `status=ACTIVE`인 경우만 유니크 제약. **purchaseYear는 현재 소유자의 구매연도로 정의(확정)** | 필수 |
| FR-PSP-04 | 영수증 미첨부 허용 | 영수증 없어도 등록 가능, `hasReceiptTag=false`로 저장 | 필수 |
| FR-PSP-05 | 내 컬렉션 조회 | 소유 Passport 목록. 상태등급·소유기간·최근진단일 파생 필드 포함, 페이지네이션 | 필수 |
| FR-PSP-06 | 여권 상세 조회 | 단건 조회 | 필수 |
| FR-PSP-07 | 여권 삭제(영구) | 소프트 삭제, **복구 불가(확정)**. 삭제 전 "기록이 모두 사라집니다" 경고 필수 | 필수 |
| FR-PSP-08 | 삭제 후 재등록 | 동일 시리얼+구매연도로 재등록 시 **새 Passport row(새 id)** 생성, 이전 이력과 연결하지 않음(확정) | 필수 |
| FR-PSP-09 | 시리얼 카메라 스캔/OCR | 카메라로 시리얼 자동 인식 | 범위 밖(로드맵) |

**수용 기준**
- 이미 `ACTIVE` 상태로 등록된 시리얼+구매연도 조합은 재등록 시 409 `SERIAL_ALREADY_REGISTERED`
- 영수증 미첨부 등록도 정상 처리되어야 함

### 3.3 마모 진단 (Diagnosis)

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-DIA-01 | 진단 등록 | 부위별 사진(최소 1장 이상, 와이어프레임 기준 4장 권장) 업로드 → `WearDiagnosisEngine.diagnose()` 호출 → 결과 저장 | 필수 |
| FR-DIA-02 | 진단 결과 산출 | 항목별 점수(마모/코팅벗겨짐/변색/부자재상태, 0~100) + 종합등급(GOOD/NEEDS_CARE/URGENT) + 판정 근거 텍스트 | 필수 |
| FR-DIA-03 | 진단 유형 구분 | 자가진단(SELF) / 매장 공식진단(STORE) 태깅 | 필수 |
| FR-DIA-04 | 진단 이력 조회 | Passport별 진단 목록, 페이지네이션, 직전 진단 비교용 데이터 포함 | 필수 |
| FR-DIA-05 | 등급 추이 제공 | 시계열 등급 변화(예: A→B) 조회용 데이터 | 필수 |
| FR-DIA-06 | 진단 등록 직후 알림 트리거 | 등록 즉시 Lifecycle Curator 평가 호출 | 필수 (3.4와 연동) |
| FR-DIA-07 | AI 엔진 교체 가능 구조 | `WearDiagnosisEngine` 인터페이스, `application.yml`의 `wear-diagnosis.engine` 값으로 `rule-based`/`ai` 전환 | 필수 |

**수용 기준**
- 진단 등록 시 이전 진단이 있으면 비교 근거(`evidenceText`)에 변화량이 반영되어야 함
- 진단 원본 사진(`imageUrls`)은 공개 API·DTO에 노출되지 않음

### 3.4 타이밍 알림 (Notification / Lifecycle Curator)

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-NOT-01 | 진단 직후 즉시 평가 | 진단 결과가 NEEDS_CARE/URGENT면 즉시 알림 생성 | 필수 |
| FR-NOT-02 | 재진단 리마인드 스케줄러 | 매일 1회 실행, (오늘−최근진단일 또는 등록일 중 늦은 쪽) > 90일 && 최근 미확인 리마인드 없음 → SELF_CARE 리마인드 생성 | 필수 |
| FR-NOT-03 | 알림 유형 분기 | NEEDS_CARE→SELF_CARE, URGENT→STORE_SERVICE, 장기소유+반복URGENT→REPURCHASE | 필수 |
| FR-NOT-04 | 알림 근거 표시 | `reasonFactors`(마모도·사용빈도·계절·경과일)를 응답에 포함 | 필수 |
| FR-NOT-05 | 알림 목록/읽음/무시 | 조회, 읽음 처리, 무시 처리 | 필수 |
| FR-NOT-06 | Care-First 재구매 조건 | 재구매 제안은 (a)수선불가 손상 (b)소유기간 장기 (c)고객이 관심 표명 — 세 조건 중 하나일 때만 노출 | 필수 |
| FR-NOT-07 | 알림 발송 상한 | 개체당 월 발송 상한, "지금은 아니다" 선택 시 다음 주기로 연기 | 필수 |
| FR-NOT-08 | 마일스톤(기념) 알림 | 소유 N일 도달 등 기념 알림 | 미확정(4.1 참고) |
| FR-NOT-09 | 알림에 종합점수 표시 | "종합 68점" 형태 점수 노출 | 미확정(4.1 참고) |
| FR-NOT-10 | 푸시 알림(FCM/APNs) | 인앱 알림 외 푸시 발송 | 범위 밖(로드맵) |

**수용 기준**
- 같은 리마인드가 중복 생성되지 않아야 함(스팸 방지 조건 적용)
- Care-First 조건 미충족 시 재구매 알림이 절대 발생하지 않아야 함

### 3.9 여권 승계 (Transfer) — 신규

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-TRF-01 | 승계 코드 발급 | 원 소유자가 `POST /api/passports/{id}/transfer-code` 호출, 6자리 코드 생성. `OwnershipTransfer` row 생성(status=ISSUED) | 미확정(4.1 참고, 데모 포함 여부 확인 필요) |
| FR-TRF-02 | 승계 대상 미리보기 | 코드로 제품 정보(모델명·등급·소유기간) 조회, 승계 확인 모달용 | 상동 |
| FR-TRF-03 | 승계 실행 | 코드+재입력 검증 → `Passport.ownerAccountId` 및 `purchaseYear`(새 소유자의 실제 구매연도로) 갱신, `OwnershipTransfer.status=REDEEMED` 처리. 기존 이력은 유지하되 이전 소유자 개인정보는 마스킹 | 상동 |

## 4. 미확정 사항 (팀 확인 필요)

1. ~~여권 승계를 이번 데모에 포함할지 여부~~ → purchaseYear 정의·삭제 정책은 확정됨(3.2 참고). 승계 기능 자체의 데모 포함 여부는 여전히 확인 필요
2. **승계 후 진단 원본 사진 접근 범위** — 마스킹 대상에 사진 포함 여부
3. **공식 케어 예약의 실제 구현 수준** — 버튼(CTA) vs 매장·시간슬롯 실제 예약 시스템
4. **Notification "기념" 타입 + 종합점수 필드** — 이번 MVP 포함 여부
5. **TimelineEvent 유형 필드** — 이번 MVP 포함 여부

## 5. 범위 밖 (Out of Scope, 확정)

- Concierge 헤리티지 스토리(구매 전), AR 제품 히스토리 조회(구매 중) — 프런트엔드 전용, 백엔드 API 없음
- 정품·리세일 공식 인증서 발급
- 연말 리캡, 게이미피케이션(스티커·뱃지)
- 소셜 로그인, MCM 멤버십 연동
- 카메라 OCR 시리얼 자동 인식
- FCM/APNs 푸시 알림
- 매장 직원 전용 로그인·권한 체계 (진단 유형 태깅으로 대체)

## 6. 비기능 요구사항

| 구분 | 내용 |
|---|---|
| 보안 | 비밀번호 해시 저장, JWT 만료·위조 시 401, 리소스 소유자 검증(비소유자 접근 시 403) |
| 프라이버시 | 영수증 이미지·진단 원본 사진은 비공개 API/DTO에서만 노출. 승계 시 이전 소유자 개인정보 마스킹 |

| 아키텍처 | 단일 Spring Boot 모놀리스, 패키지-바이-피처 |
